# Report B2: galleries, viewer, video, GitHub activity (behaviour)

Vanilla ES modules, no dependencies, no styling. Each exports an `init*` that finds its hooks, returns `null`/`[]` when they are
absent and never throws. Hook names follow the skeleton (`prototypes/skeleton/index.html`); where the job text and the skeleton
differ, both are accepted (noted below). Every module has a header comment with the full hook/attribute/event list.

## Files
| File | Role |
|---|---|
| `scripts/core/modal.js` | shared helpers: `emit`, scroll lock (`body.is-locked` + `scroll:lock`/`scroll:unlock` document events for Lenis), reduced-motion check, bounded close hook, focus return |
| `scripts/core/viewer.js` | `initViewer`, `openViewer(items, index, fromEl)`, `closeViewer`, `itemFromElement`, `setViewerTransition(fn)` |
| `scripts/core/video.js` | `initVideo`, `openVideo(clip, fromEl, at)`, `closeVideo`, `setVideoTransition(fn)` |

## Events (CustomEvent, bubble to `document`)
| Event | Target | detail |
|---|---|---|
| `gallery:change` | gallery root | `{ index, count, slide, previous, direction, reason: button\|dot\|key\|drag\|scroll\|viewer }` (only the destination during a programmatic scroll) |
| `viewer:open` / `viewer:change` / `viewer:close` | viewer dialog | `{ items, index, item?, direction?, from }` |
| `video:open` / `video:close` | video dialog | `{ clip, from }`, close adds `time` |
| `activity:state` / `activity:ready` | activity root | `{ state }` / `{ days, summary }` |
| `scroll:lock` / `scroll:unlock` | document | none (first dialog opens / last closes) |

Design hook: `setViewerTransition(fn)` / `setVideoTransition(fn)`; `fn(ctx)` runs on open (not awaited) and on close (awaited up to 1.2 s before
the dialog really closes, Escape included). Viewer `ctx = { phase, from, image, dialog, item, index, reduced, loaded }`. Use it for Flip or a View Transition from `from`'s image.

## Choices worth knowing
- Gallery and viewer are decoupled: with the skeleton markup (`button[data-lightbox]` per slide, `button[data-video-open]` for the film slide) the
  viewer/video delegates do the opening and the gallery only steps, counts and reports. For bare slides (an `<img>` with `data-title` on the `<li>`) the gallery opens the viewer itself.
  When the viewer closes on a gallery slide the track follows to the slide last seen.
- Viewer image uses the best `srcset` candidate for the screen (max 2400w), not the card's thumbnail. Neighbours are preloaded.
- Escape (`cancel`) is intercepted so the close transition can run; focus returns to the opener in the `close` handler.
- Video: `play()` is called inside the opening click, so it has sound; on close it pauses, removes `src`/`poster` and calls `load()` so nothing keeps buffering.
- Activity: the calendar is `role="group"` with an `aria-label`, cells are `aria-hidden`, and the hidden summary carries the numbers; the skeleton's `role="img"` is replaced by that. Text values are final immediately (no count-up inside the module).
- Only functional inline styles are written: `touch-action:pan-y` on the viewer stage, `scroll-snap-type:none` on a track while mouse-dragging, the summary's visually-hidden clip, and the `--tip-*`/`--weeks` custom properties.

## Design must match
- The skeleton legend uses `[data-l="0..4"]`; the grid uses **`data-level`**. Style by `data-level` and update the legend.
- Style `.is-hl`, `.is-on` (tip), `[data-state]`, `.is-loading` etc. yourself; none of them has any default look.
- The skeleton has no `[data-gallery-dots]`/`[data-gallery-count]`; add them if the design wants dots or a counter (the module fills them).

## Not done / gaps
- WebKit and real touch devices not run (the swipe was dispatched as touch PointerEvents; native touch scrolling of the gallery is the browser's).
- Calendar cells are not keyboard-focusable (365 tab stops would be worse); keyboard users get the summary and the stat buttons.
- No count-up in `activity.js`; `data-value` is there for the motion layer.
- No lightbox pinch-zoom; no `Home/End` in the viewer.
