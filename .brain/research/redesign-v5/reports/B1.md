# Report B1: behaviour core (theme, stats, contact, toast)

## What was built
Four design-agnostic vanilla ES modules in `scripts/core/`. Each exports an `init*` function that finds its hooks,
does nothing if they are absent, never throws (body wrapped in try/catch), writes only state classes/attributes
(plus the theme click-point CSS variables) and has a header comment listing hooks, writes and events.

| Module | Exports | Notes |
|---|---|---|
| `scripts/core/theme.js` | `initTheme`, `getTheme`, `setTheme`, `toggleTheme` | Light default, follows OS until chosen, key `portfolio-theme`. Flash-free head bootstrap is in the header comment. |
| `scripts/core/stats.js` | `initStats` | Port of the old `js/stats.js` logic (same localStorage keys, locks, `/api/stats` contract). |
| `scripts/core/contact.js` | `initContact`, `openMessage`, `closeMessage` | Native `<dialog>`, FormSubmit AJAX to `mcleinjeionza06@gmail.com`. |
| `scripts/core/toast.js` | `initToast`, `showToast`, `hideToast` | `showToast` works without `initToast`; `stats.js` and `contact.js` import it. |

Wire-up: `initToast(); initTheme(); initStats(); initContact();` (order does not matter).

## Hooks read and state written

| Module | Hooks read | Attributes / classes written |
|---|---|---|
| theme | `[data-theme-toggle]` (delegated click), `--theme-color-light` / `--theme-color-dark` on `:root` (fallbacks `#EDEEF0` / `#0D0E10`), `meta[name=theme-color]` | `html[data-theme=light\|dark]` (always set), `html[data-theme-transition]` during a view transition, `--theme-x/--theme-y/--theme-r` on `html` during a pointer/keyboard toggle (px; removed after), toggle `aria-pressed` (true = dark) and `data-theme-current`, all theme-color metas get the active colour, `localStorage portfolio-theme` |
| stats | `[data-stats-visits]`, `[data-stats-likes]`, `[data-stats-like]` | count elements: text `1,234`, `data-count`, `is-loading` then `is-ready`; like button: `aria-pressed`, `is-liked`, `is-busy` + `aria-busy`, transient `is-just-liked` / `is-already` (~900ms, skipped under reduced motion); `localStorage site_total_visits/likes, site_user_has_visited/liked` |
| contact | `[data-message-open]` (delegated), `dialog[data-message]`, `[data-message-form]`, `[data-message-close]`, `[data-message-submit]`, `[data-message-status]`, `[name=_honey]` | dialog + form `data-state=idle\|sending\|success\|error`, dialog `is-open`, form `is-loading` + `aria-busy`, submit `disabled` while sending, fields `aria-invalid`, status `is-success`/`is-error` + text, `body.is-locked` while open |
| toast | `[data-toast]`, `[data-toast-text]`, optional `data-duration` | region `is-visible`, `data-state=visible\|hidden`, `data-tone=info\|success\|error`, text (cleared after hide) |

## Events (CustomEvent on `document`)

| Event | detail | Emitted by |
|---|---|---|
| `theme:change` | `{ theme, previous, source: init\|user\|system\|storage\|api, x, y }` | theme (inside the DOM update, so listeners see the new theme) |
| `stats:update` | `{ metric: visits\|likes, value, previous, source: cache\|network\|optimistic\|rollback }` | stats |
| `stats:like` / `stats:like-failed` | `{ count }` / `{}` | stats |
| `message:open` / `message:close` | `{ dialog }` | contact |
| `modal:open` / `modal:close` | `{ name: 'message', dialog }` | contact (generic hook so the smooth-scroll layer can stop/start Lenis; other modals should emit the same) |
| `message:sending` / `message:sent` / `message:error` | `{}` / `{}` / `{ reason }` | contact |
| `toast:show` (listened) | `{ message, tone?, duration? }` | anyone can dispatch it |
| `toast:shown` / `toast:hidden` | `{ message, tone }` | toast |

CSS hint for the circular theme reveal: `::view-transition-new(root){ clip-path: circle(0 at var(--theme-x) var(--theme-y)) }`
animated to `circle(var(--theme-r) at var(--theme-x) var(--theme-y))`, scoped with `html[data-theme-transition]`.
Light CSS should declare `color-scheme: only light` under `[data-theme=light]` (old test: Android auto-darkening) and
`color-scheme: dark` under `[data-theme=dark]`.

## Deliberate differences from the old code
- `theme.js`: `data-theme` is now set for both values (old code removed it for dark); default is light unless the OS is dark.
- `stats.js`: a failed **like** no longer falls back to a direct Abacus `/hit/` (old code did); it rolls the like back
  (count, `is-liked`, flag) and shows an error toast so the visitor can retry. Visits never hit Abacus directly (unchanged).
  Reads may still fall back to Abacus `/get/` as before. The draggable pill is not ported (no floating pill in v5).
  Count elements keep their existing text until a number is known (no fake "0").
- `contact.js`: a 200 response whose JSON says `success: false/"false"` (FormSubmit's reply for a not-yet-activated
  address, see TODO) is reported as an error instead of a false "sent". Added a 15s timeout, honeypot short-circuit
  (a filled `_honey` fakes success and sends nothing), explicit Tab trap and `aria-invalid`.

## Verification
Throwaway harness `prototypes/b1-harness/` (copy of the skeleton's hook markup, served by `node tests/serve.mjs 4317`,
driven by Chrome via `@playwright/test`), all third parties mocked (`/api/stats`, Abacus, FormSubmit routed; no real
counter or email touched; `portfolio.test` proxy used to simulate a non-local, non-webdriver browser). **40 checks passed**:
- Theme: light default, dark OS followed live until a choice, choice persisted across reload and ignores later OS
  changes, both theme-color metas updated from the CSS vars, view transition ran with `--theme-x/y/r` and the vars were
  cleaned up, reduced motion swaps instantly, keyboard toggle works.
- Stats: first real visit increments once across reloads and cleared sessions; failed first visit is not marked counted
  and retries; no Abacus `/hit/` ever; local/automated browsers only read; like once (repeat clicks and reloads send
  no second increment, toast announces); cached totals render before the network answers; failed like rolls back.
- Contact: opens with first field focused, Tab/Shift+Tab stay inside, honeypot skipped, Escape / close button / backdrop
  close, focus returns to the right opener, `is-locked` and `is-open` cleared; empty and invalid-email submits blocked;
  sending state; POST to `https://formsubmit.co/ajax/mcleinjeionza06@gmail.com` with `Accept: application/json` and all
  hidden fields; success status + toast, form reset, auto-close; HTTP 500 and `success:"false"` show the error with the
  direct email and keep the text; filled honeypot sends nothing.
- Empty page: all four inits no-op without errors.
The harness was deleted afterwards. Not run: WebKit/iPhone projects, axe, screenshots (no styling in these modules).

## Known gaps
- Modules are untested against the final design; designers must style the state hooks above.
- Escape/backdrop close and focus return rely on the native `<dialog>`; the non-native fallback is minimal and untested.
- `body.is-locked` is the scroll-lock class (same as the old site); the Lenis/motion layer should listen to `modal:open/close` or that class.
