## 2. vercel.json (headers only; no redirects/rewrites/routes; api/ untouched)
The repo folders are `/css` and `/js` (the brief said /styles, /scripts), so those are the sources used.
- `/assets/(.*)` -> `public, max-age=604800, stale-while-revalidate=86400`: images/video one week, SWR one day. Not fingerprinted, so not immutable.
- `/assets/fonts/(.*)` -> `public, max-age=31536000, immutable`: placed AFTER the /assets rule because both match and Vercel applies later matching rules over earlier ones for the same key. Fonts are self-hosted woff2 whose names don't change.
- `/vendor/(.*)` -> one year immutable: pinned library versions. CAVEAT: filenames are not hashed, so a future vendor update must change the path (or accept stale clients up to a year).
- `/` -> `public, max-age=0, must-revalidate`: HTML always revalidates (ETag 304).
- `/css/(.*)` and `/js/(.*)` -> `public, max-age=300, must-revalidate`: not fingerprinted; 5 min caching, then revalidate.
- robots.txt, sitemap.xml: no rule, Vercel defaults. api/*: no rule, functions set their own headers.
- Validation: parses as JSON; only the `headers` key with `source` path-to-regexp patterns (`/x/(.*)`) and `{key,value}` arrays, the documented form. Not deployed, so not validated by Vercel itself.
- Caveat: `/index.html` direct requests are not covered by the `/` rule.
- Nothing committed or deployed.
