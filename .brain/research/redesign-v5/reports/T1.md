# T1: v5 layout audit tool

## What it is
`npm run audit:v5` runs `tests/v5-audit.spec.mjs` against any page of the repo. The page comes from `V5_PATH`
(default `/`), for example `V5_PATH=/prototypes/direction-a/ npm run audit:v5`. Serving is the existing
`tests/serve.mjs` on 4173 (webServer reuses a running one).

One Playwright project per viewport (320x568, 390x844, 430x932, 768x1024, 1024x768, 1280x800, 1440x900,
1920x1080, 2560x1440; Chrome) plus `v5-webkit-iphone14`. Widths <= 768 are touch contexts (Pixel 7 profile),
the rest desktop Chrome. Each project runs two tests: **layout** and **reduced motion**.
Run one viewport: `V5_PATH=/x/ npx playwright test v5-audit.spec.mjs --project=v5-390x844`.

**Layout test**: waits 2.8 s (loader; `V5_SETTLE_MS`), scrolls the whole page in 0.6-viewport steps with a 260 ms
settle each (reveals and pins fire), scans the viewport at every step (so fixed, sticky and pinned states are
covered), returns to top, then checks:
- horizontal page overflow (scrollWidth vs clientWidth, max over all steps)
- visible elements/text past the left/right viewport edge
- overlapping text (line boxes of text nodes from different blocks)
- touch targets < 24x24 (touch viewports only)
- visible images not loaded (naturalWidth 0, still loading)
- console errors, page errors, failed/4xx/5xx requests (ignores `/api/`, other hosts, aborted requests, WebKit's own `Button failed to load, iconName` video-controls noise)
- axe: fails on serious/critical (moderate/minor listed as info)

**Reduced-motion test** (`reducedMotion: 'reduce'`, scroll through, back to top): every visible h1-h6/p must have
effective opacity > 0.05, no zero-area clip-path, not collapsed, not clipped away by an `overflow:hidden` wrapper
(mask reveal that never ran). Also axe colour-contrast on the final static state.

All checks are `expect.soft`, so one run shows every problem. Output per viewport:
`test-results/v5-audit/<path-slug>/<viewport>.png` (full page, CSS px), `<viewport>.txt` (readable summary),
`<viewport>.json`, `<viewport>.reduced-motion.txt|json`. The summary is also printed and attached to the report.
`<path-slug>` is derived from `V5_PATH` (`/` -> `root`, `/prototypes/direction-a/` -> `prototypes-direction-a`),
so audits of different pages (and parallel runs) do not overwrite each other.

## Files
- `tests/v5-audit.spec.mjs`, `tests/v5-audit-helpers.mjs` (new)
- `playwright.config.mjs`: `v5Projects` (10 projects, `testMatch` only the new spec, own
  `outputDir: test-results/v5-audit/_pw` so a v5 run never wipes the default `test-results` and vice versa
  for other pages' audit folders). The only change to existing projects: the 3 base targets got
  `testIgnore: [/timing\.spec/, /v5-audit\.spec/]` (otherwise `npm test` would also run the audit without its
  per-viewport metadata). `--list` confirms desktop-chrome lists 0 v5 tests.
- `package.json`: script `audit:v5`.

## Verification
Ran against the current site (`V5_PATH=/`): 20 tests, about 4 min on this machine. Result: 5 layout tests fail
(320, 390, 430, 768, webkit), 4 desktop layouts and all 10 reduced-motion tests are clean.

Known-bad fixture (temporary page, since deleted) with a 700px box, overlapping text, 12px tap target, missing
images, console error, 404s, `/api` call, never-revealed paragraph/mask heading, low-contrast text, sr-only text:
every real problem was found, `/api/` and the sr-only text were not reported.

False positives found while spot-checking against screenshots and fixed in the tool:
1. `.sr-only` text (1px clipped box, text spills out) counted as overlapping/overflowing.
2. Fixed nav passing over scrolling content counted as overlap (now only judged at scrollY ~ 0).
3. Text content boxes are taller than glyphs, so tight display leading ("04 / ACTIVITY" label above 900-weight
   h2) overlapped; rects are now shrunk to ~glyph body (20% top, 15% bottom).
4. Inline child inside its parent's text flow (`em` in an `h2`) counted; line-clamped text hidden by the
   element's own `overflow:hidden` counted; both fixed.
5. Lazy images inside offscreen carousel slides counted as "not loaded"; now only images that are rendered,
   not transparent/aria-hidden and not clipped away count.
6. axe colour-contrast on scroll-scrubbed (dimmed) headings; flagged nodes are scrolled into view (centre,
   then top) and re-tested, kept only if they still fail.

Spot checks: 320 overflow confirmed by screenshot (gallery "next" button and project text cut at the right
edge); 1440 label/heading overlap confirmed false (fixed in 3).

- Touch phones/tablet: `a.text-link` "mulat-media.vercel.app" (149x22) and "github.com/Mclein31" (150x19) under
  24px; at 768 also footer links GitHub/LinkedIn/Email/Back to top (22px high).

- 390, 430, 768 and all desktops: no overflow, no overlap, no console errors, images load.

## Limitations
- Overlap/overflow are geometric heuristics on text line boxes; text hidden by `mix-blend`, `clip-path` or
  masks is not understood. An overlap of two blocks where one has an opaque background in between is reported.
- Fixed elements are only compared against content at the page top; sticky layers with transparent background
  are compared everywhere.
- Reduced-motion check cannot tell an inactive slide with opacity 0 from a broken reveal: the summary says
  "check by eye" for those.
- axe runs once per viewport at the top of the page (plus re-tests of flagged contrast nodes), not on every
  interactive state.
- `/api/` console 404s are ignored only when the console message carries the `/api/` URL; app errors that merely
  log a failed API call would still show.
- Running the other specs wipes `test-results/` (their default outputDir) including old audit output; re-run
  the audit afterwards or copy the folder.
- Soft-assertion failures print Playwright code frames per category; the readable summary is the first block.
