# Report I1: skeleton wiring (one entry, one scroll lock, final hooks)

`prototypes/skeleton/index.html` is now a working, unstyled site: it loads `/scripts/main.js` as the only module and every behaviour module in `scripts/core/` is live. Design-neutral: the inline `<style>` in the skeleton is still the review-only reset, nothing was designed. The direction prototypes, the old `js/` and `css/` folders and `tests/` were not touched.

## What exists (earlier agent's work, read and verified; the wrap-up added only the verify script and this report)
| File | Role |
|---|---|
| `scripts/main.js` | The single entry. Inits every core module in the order below, each step in its own try/catch (`step()`), then `settle()` and `site:ready`. |
| `scripts/core/lock.js` | The ONE scroll-lock owner: keyed registry (`lockScroll(key)`, `unlockScroll(key)`, `isScrollLocked()`, `lockKeys()`), writes `html.is-scroll-locked` + `body.is-locked`, emits `scroll:lock` / `scroll:unlock`. `setLockHandler(fn)` lets motion.js plug in the Lenis policy; with no handler (or no Lenis) it sets inline `overflow:hidden` on `<html>` and restores the previous value. |
| `scripts/core/motion.js` | Registers the handler: while a key is held and Lenis runs, `lenis.stop()`; released, `lenis.start()`. Re-exports `lockScroll` / `unlockScroll` / `isScrollLocked` from lock.js; `scrollTo()` refuses while locked. |
| `scripts/core/modal.js` | Re-exports the same lock functions for viewer (`'viewer'`) and video (`'video'`). |
| `scripts/core/contact.js` | Uses `lockScroll('message')` / `unlockScroll('message')` from lock.js (no private locking left). |
| `scripts/core/nav.js` | `lockScroll('menu')` / `unlockScroll('menu')` through motion.js. |
| `scripts/core/page.js` | New: `[data-year]` and delegated `[data-copy]` (+ `data-copy-label`) with toast. |
| `prototypes/skeleton/index.html` | Head: flash-free theme bootstrap, `is-intro`/`is-ready` bootstrap, CSS failsafe keyframes (`1%, 100%` stops), `/vendor/lenis/lenis.css`, `<script type="module" src="/scripts/main.js">`. Body: gallery dots + count hooks on all 5 galleries, legend swatches on `data-level`, nav/menu/intro hooks. All asset and script paths are root-absolute. |

## Init order (`scripts/main.js`, every step isolated)
1. `theme`: `initTheme()` (toggles + theme-color; the bootstrap in `<head>` already set `data-theme`)
2. `intro`: `initIntro()` (decides play/skip, owns `is-intro` / `is-ready` and the 2.5 s JS failsafe)
3. `motion`: dynamic import of `motion.js` (started in parallel with 1-2) then `initMotion()` (GSAP, ScrollTrigger, Lenis, lock handler)
4. `nav`: `initNav()` (needs motion; skipped with a warning if motion failed)
5. `toast`: `initToast()`
6. `page`: `initPage()`
7. `galleries`: `initGalleries()`
8. `viewer`: `initViewer()`
9. `video`: `initVideo()`
10. `contact`: `initContact()`
11. `stats`: `initStats()`
12. `activity`: `initActivity()` (main grid + contact mini grid; both load lazily when near the viewport)
Then design steps (`designSteps`, empty), then `settle()`, `html[data-site-ready="true"]` and the `site:ready` event `{ ok[], failed[], ms }`.

`settle()` calls `motion.refresh()` once after window load + `document.fonts.ready` + the non-lazy images, and again on `activity:ready` and `intro:done`. motion.js also refreshes on every late `<img>` / `<video>` load.

## Notes and gaps
- WebKit logs its own native video-controls icons (`Button failed to load, iconName = *-placard ... src = blob:`) as console errors; the script ignores exactly that pattern. It is browser UI, not the page.
- WebKit's default Tab does not stop on links, so the menu trap is tested with Option+Tab there (Chromium with plain Tab). Plain Tab in Safari is a visitor setting, noted in M1.
- Activity and the contact mini grid load only when within ~1000 px of the viewport (by design, activity.js); the script scrolls to them first.
- Chrome Pixel 7 was not run (only the two required targets). The hook table in the skeleton is the contract; styling of every state class is still the design layer's job.
- Not committed. Left running: nothing (the test server on 4321 was started by me; stop it with `pkill -f "tests/serve.mjs 4321"`).
